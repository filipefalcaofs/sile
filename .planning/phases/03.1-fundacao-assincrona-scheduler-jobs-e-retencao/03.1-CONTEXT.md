**Gathered:** 2026-06-13

<domain>
## Phase Boundary

Ativar a infraestrutura assíncrona pronta do Laravel 13 ainda não usada: scheduler com primeira rotina real (pruning de retenção), jobs em fila (Redis) com retry/timeout/relatório auditado para as importações REDESIM e CNAE, throttle parametrizado nas rotas públicas, retenção de `access_logs` por pruning agendado e retry/backoff parametrizado no HTTP client. Infraestrutura habilitadora para prazo BAP (HU-134), SLA (HU-144/147) e integrações (HU-146).

Fora do escopo (YAGNI): Horizon, fila dedicada por integração (`Queue::route()`), `Http::pool`/`Concurrency`, e o stack Docker de produção (Dockerfile/supervisord/compose Portainer) — produção é apenas DOCUMENTADA nesta fase; o stack entra no esforço de deploy. Política completa de retenção/LGPD da trilha de auditoria fica na Fase 12.
</domain>

<decisions>
## Implementation Decisions

### Driver e infraestrutura de fila
- Manter **Redis** (já é `QUEUE_CONNECTION`/`CACHE_STORE`/`SESSION_DRIVER`; dev compose tem o serviço). Zero dependência nova.
- As migrations `jobs`, `failed_jobs` e `job_batches` JÁ EXISTEM (verificado em `database/migrations/0001_01_01_000002_create_jobs_table.php`, padrão do Laravel 11+). `failed_jobs` grava no banco mesmo com Redis (driver `database-uuids`). Os jobs apenas USAM essas tabelas — NÃO criar migration nova (duplicar quebraria `migrate:fresh`). Jobs falhos visíveis e reprocessáveis — nunca falha silenciosa.

### Scheduler + primeira rotina real
- `composer dev` ganha `php artisan schedule:work` (de 4 para 5 processos concorrentes).
- Agendamento em `routes/console.php` via `Schedule::command(...)` com `->withoutOverlapping()` e `->onOneServer()` — padrão idempotente herdado por HU-134 (prazo BAP) e HU-147 (escalonamento SLA).
- **Primeira rotina real = pruning de `access_logs`** (`model:prune`), diário. Mata scheduler real + retenção numa só entrega; sem rotina artificial.

### Retenção de access_logs (LGPD)
- `AccessLog` recebe `MassPrunable` com `prunable()` por `created_at` < hoje − `retencao.access_logs.dias` (parâmetro).
- A trilha de auditoria de decisões (`activity_log`/RN-002) **NÃO é podada** — retenção longa por compliance; fica explicitamente fora.

### Jobs das importações
- `ImportRedesimJob` envelopa `RedesimImportService` (existente) com `$tries`/`$timeout`/`backoff()`; comando `redesim:importar` ganha `--queue` (modo síncrono preservado para homologação local).
- `ImportCnaeJob` envelopa `CnaeImportService` (existente); novo comando `cnae:importar {arquivo} {--queue}` — caminho assíncrono de reimportação oficial (hoje só via re-seed). Sem volume que exija `Bus::batch` agora (1.331 linhas) — job único; `Bus::batch` fica anotado para quando houver volume.
- A auditoria de resultado já existe nos serviços — preservar.

### Throttle parametrizado
- `RateLimiter::for('cnpj-lookup')` com limite lido de `seguranca.throttle.cnpj_lookup.por_minuto`; aplicado em `portal/empresas/consultar-cnpj` (middleware `throttle:cnpj-lookup`). 429 ao exceder. Padrão para HU-069 e EP07.

### HTTP client parametrizado
- `BrasilApiCnpjLookup` passa a ler `retries`, `timeout` e novo `backoff_ms` de **parâmetros** (`integrations.cnpj_lookup.*`), com fallback nas constantes de `config/sile.php` (mantém o padrão Settings::get da Fase 2).

### Parâmetros novos (catálogo HU-014)
- `retencao.access_logs.dias` — integer, default 365, `min:30 max:3650`, grupo `retencao`.
- `seguranca.throttle.cnpj_lookup.por_minuto` — integer, default 30, `min:1 max:300`, grupo `seguranca`.
- `integrations.cnpj_lookup.retries` — integer, default 2, `min:0 max:5`, grupo `integracoes`.
- `integrations.cnpj_lookup.timeout` — integer (s), default 8, `min:1 max:30`, grupo `integracoes`.
- `integrations.cnpj_lookup.backoff_ms` — integer, default 200, `min:0 max:5000`, grupo `integracoes`.
- Atualizar as asserções de contagem do catálogo nos testes (hoje 20).

### Produção (documentada)
- `docs/deploy/producao-assincrona.md`: cron `* * * * * php artisan schedule:run`, `queue:work`/Horizon, variáveis de fila, e aviso de que o stack Docker de produção é trabalho de deploy futuro.

### Claude's Discretion
- Nomes de jobs/commands, estrutura dos testes, valores de `backoff()` do job, estrutura dos jobs/listeners (as tabelas de fila já existem — sem migration nova).
</decisions>
