<objective>
Ativar o scheduler do Laravel com a primeira rotina real do SILE: pruning diário de `access_logs` com retenção parametrizada (LGPD). Mata dois critérios numa entrega — scheduler real idempotente (padrão herdado por HU-134/HU-147) e retenção de dados — sem rotina artificial. A trilha de auditoria de decisões (`activity_log`/RN-002) fica explicitamente FORA do pruning (retenção longa por compliance; política completa na Fase 12).

Purpose: fecha os Success Criteria #1 (scheduler ativo com rotina real idempotente E AUDITADA) e #4 (retenção parametrizada de access_logs; activity_log fora) do ROADMAP.
Output: `composer dev` com `schedule:work`; `routes/console.php` agendando `model:prune`; `AccessLog` com `MassPrunable`; listener `AuditModelsPruned` gravando auditoria da poda; testes de agendamento, de pruning e de auditoria.

Nota (auditoria do MassPrunable): `MassPrunable` apaga em massa SEM disparar model events de delete, mas o Laravel dispara `Illuminate\Database\Events\ModelsPruned` (uma vez por chunk de poda) com o nome do modelo e a contagem. É esse evento que a rotina audita — daí o listener, em vez de `HasAuditoria` (que `AccessLog` não usa, pois já É auditoria de acesso).
</objective>

    namespace App\Listeners;

    use App\Models\AccessLog;
    use App\Support\Audit\AuditService;
    use Illuminate\Database\Events\ModelsPruned;

    class AuditModelsPruned
    {
        public function __construct(private readonly AuditService $audit) {}

        public function handle(ModelsPruned $event): void
        {
            // Só auditar a poda de access_logs — não poluir se outros Prunable surgirem.
            if ($event->model !== AccessLog::class) {

                properties: ['modelo' => $event->model, 'removidos' => $event->count],
                rulesVersion: 'retencao-access-logs-v1',
            );
        }
    }
