# PLAN 14-02 — Onda 1: Documentos (HU-112 a 115) + fundação de execução de IA

> Onda 1 do AI-SPEC. Consome a Onda 0 (config multi-provider + ponte runtime + toggles `features.ia_*`). Cria a fundação de EXECUÇÃO (compartilhada pelas Ondas 1-3) e as 4 funções documentais, todas como SUGESTÃO revisável, em fila, atrás de toggle, auditadas, testadas com o fake do SDK (sem rede/custo).

## Objetivo

Acelerar a leitura documental do analista: extrair texto (OCR), classificar o tipo, marcar ilegibilidade e apontar inconsistências documento × declaração — tudo como sugestão marcada, nunca decisão (AI-SPEC Failure Mode #1).

## Critério de pronto (anti-fachada)
- Cada função é um Agent real (`app/Ai/Agents`) com saída estruturada; executa via Job na fila; respeita o toggle (`features.ia_*` OFF ⇒ NÃO chama o provedor, degrada honesto).
- Resultado persistido em `ai_suggestions` (status sugestão, nunca decisão), auditado RN-002 (provider/modelo/prompt_version/tokens; sem api_key; `personal_data` quando há PII).
- Guardrails: `confianca` < limiar parametrizado ⇒ `escalada_humano`; `fonte` obrigatória no schema; minimização de PII no input.
- Testes com `MeuAgent::fake([...])` (`#[Group('ia')]`), provando sucesso, degradação (toggle OFF ⇒ `assertNeverPrompted`), auditoria sem segredo e status nunca-decisão. golden cases provisórios (datasets reais = pendência SEDUR).
- `composer test` SQLite verde; pint/tsc/build verdes.

## Dependências
- Onda 0 (entregue): `AiConfiguration`, `AiConfigResolver`/`AiConfigServiceProvider` (ponte → `config('ai.*')`), toggles `features.ia_*`, permissão `manter-config-ia`.
- Reusa: jobs/fila + retry/backoff (Fase 3.1, molde `DecidirFluxoExpressoJob`/`GerarExportacaoJob`), `AuditService` (RN-002), Settings/Parameter (HU-014), Storage de documentos (Fase 8 `ViabilityRequestDocument`), ficha de análise (Fase 10 `AnalysisRecordController`/`gestao/ficha-analise/show.tsx`).
- API real do `laravel/ai` v0.8.1: `Agent` (interface) + `Promptable` (trait), `HasStructuredOutput::schema(JsonSchema): array<string,Type>`, `StructuredAgentResponse` (ArrayAccess), `Files\Image::fromStorage`/`Files\Document::fromStorage`, fake POR AGENT (`MeuAgent::fake([...])`). `Usage` só tem tokens (sem custo).

### Task 3 — HU-112 OCR + HU-114 ilegibilidade (leitura por visão)
- **`app/Ai/Agents/LeituraDocumentoAgent.php`** (`make:agent --structured`): visão multimodal; schema `{ texto: string, legivel: bool, confianca: enum[baixa,media,alta], motivo_ilegibilidade?: string, fonte: string(required) }`. `instructions()` proíbe inventar dado ausente.
- **`app/Services/Ai/LeituraDocumentoService.php`**: gate (`ia_ocr`); monta anexo `Files\Image::fromStorage($doc->path,$doc->disk)` (imagem) ou `Files\Document::fromStorage(...)` (pdf); despacha o Job; persiste `AiSuggestion` type `ocr` (e marca ilegibilidade quando `legivel=false`/confiança baixa → `escalada_humano`).
- Integração: a sugestão (texto/legibilidade) fica consultável por documento do processo (sugestão, não verdade). Toggle `features.ia_ocr`.
- TDD (`#[Group('ia')]`, `LeituraDocumentoAgent::fake([...])`): documento legível → sugestão ocr com texto+confiança+fonte; ilegível/baixa confiança → `escalada_humano` (não trata como verdade); toggle off → `assertNeverPrompted`.
