# Fase 2.4 (INSERTED) — Template SaaS de listagens e dashboard

## Objetivo

Elevar o template do SILE ao padrão de produto SaaS premium: biblioteca de componentes reutilizáveis de listagem/dashboard (data table tipada com ordenação, filtros, busca, paginação e page size; KPI cards; skeleton; toolbar) aplicada às páginas reais da gestão — eliminando duplicações (`PageBreadcrumb`, estilos de ação, card-contêiner, busca com debounce) e estabelecendo o padrão visual das Fases 3–15.

## Referências analisadas

- **SILE Design System** (`SILE Design System.zip`) — derivado deste codebase; fonte da identidade: Outfit, brand `#465fff`, neutros frios, hairlines, cards `rounded-2xl`, dark mode.
- **Horizon UI (Chakra + TanStack v8)** — definição de colunas tipada (`ColumnDef<T>`), sorting controlado, KPI mini-statistics.
- **Dashtic datatable (Spruko)** — busca + page size, indicadores de ordenação, range "Mostrando X–Y de Z" + paginação numérica.
- **Rixzo projects list (Spruko)** — KPIs acima da listagem, toolbar busca/filtros/ação, badges pill, avatares, ações por linha.

## Decisões aprovadas (2026-06-11)

1. **Escopo completo**: componentes + CNAEs como listagem-modelo + KPIs reais no dashboard + migração das demais listagens da gestão.
2. **Evoluir a identidade SILE existente** — refinamento, sem re-tematização.
3. **DataTable própria** — tipada, server-driven via Inertia; zero dependências novas (consistente com a decisão da Fase 2.1).

## Direção visual

"Console institucional premium": hierarquia de página padronizada — `PageHeader` (título + breadcrumb + ações) → KPIs (quando aplicável) → `Card` único (header com título/descrição/ação primária) → toolbar (busca à esquerda; filtros e page size à direita) → tabela → footer (range + paginação). Headers de tabela em `text-theme-xs` médio com indicadores de ordenação discretos; estados completos (hover `gray-50`, focus ring `brand/12`, skeleton pulse, empty com ícone em well, disabled 50%); motion 150ms funcional (opacity/color); dark mode em tudo.

### B. Backend (TDD estrito, PHPUnit)

- `CnaeController@index`: aceitar `sort` (whitelist: `code`, `description`), `direction` (`asc`/`desc`), `per_page` (whitelist: 10, 15, 25, 50) e filtro `active` (`1`/`0`/vazio); defaults preservados (`code asc`, `Settings::get('ui.cnaes.per_page', 15)`); filtros ecoados em `filters`.
- `DashboardController` (gestão): KPIs **reais** condicionados à permissão — CNAEs ativos/total (`consultar-cnaes`), usuários ativos (`manter-usuarios`), perfis (`manter-perfis`), acessos dos últimos 7 dias (`manter-usuarios`, via `access_logs`). Nenhum delta inventado.

### C. Aplicação

- `gestao/cnaes/index.tsx` refeito como listagem-modelo: PageHeader + Card + toolbar (busca, filtro de situação, page size) + DataTable com ordenação + Pagination existente.
- `gestao/dashboard.tsx`: linha de KPI cards reais acima dos módulos.
- `gestao/usuarios`, `gestao/perfis`, `gestao/parametros` (+ `historico`), `gestao/acessos`: migrar para `PageHeader`, `Card`, `TableAction` (sem mudança de comportamento).
